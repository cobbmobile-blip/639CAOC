The Combined AOC Process, Start to Finish

A cooperative campaign runs on nine stages. The Combined Campaign Intent (TTP 1-0) is set once by the CFC, before Cycle 1, and revised rarely. Each cycle, the CFACC turns it into a Combined AOD (TTP 1-2), which drives the JIPTL (the approved, prioritized target list — planned, currently embedded in the AOD). The MAAP cell (Combat Plans) turns the JIPTL into a Package Plan (TTP 1-3, the MAAP), then builds the ACO and the Theater Comm Plan alongside it — the ACO rebuilt manually before every mission event as the battle moves, the Comm Plan set once per campaign and left alone. Both merge into the ATO, the last product before execution: every group's packages, the current ACO, and the standing Comm Plan, compiled into one tasking document. Squadrons fly against it, then file BDA, which closes the loop back into the next AOD and, occasionally, back into the Intent itself.

Stage by Stage

1

Combined Campaign Intent

Built

The CFC's statement of End State, Key Tasks, Air Phases, and the swing threshold. Set once per campaign and revised only when the campaign itself changes shape — not every cycle. Everything downstream exists to serve it.

TTP 1-0 · Intent Builder · owner: CFC · cadence: per campaign
2

Combined AOD

Built

The CFACC's weekly translation of the Intent into a cycle: this cycle's objective, apportionment by group, ALR/ROE, and the approved cross-group requirements. Pulls its main-effort and apportionment defaults straight from the current Intent revision.

TTP 1-2 · AOD Builder · owner: CFACC · cadence: every cycle
3

JIPTL

Planned

The Joint/Combined Integrated Prioritized Target List — the actual approved, graded target set for the cycle, nominated against the AOD's objective and ranked by priority. Today this lives as a table inside the AOD itself ("Approved cross-group requirements"); a standalone JIPTL product with its own nomination/approval workflow is planned but not yet built.

owner: CFACC / targeting cell · cadence: every cycle
4

Package Plan (MAAP)

Built

The MAAP cell (Combat Plans) turns JIPTL requirements into flyable packages — composition, target/location, control, tanker, EW. Pulls a cycle's requirements straight from the saved AOD.

TTP 1-3 · Package Plan Builder · owner: Combat Plans (MAAP cell) · cadence: every cycle, per package
5

ACO

Manual · DKS

The Airspace Control Order reflects the current battle state — tanker tracks, FLOT/FSCL, active control measures — and changes as the fight progresses, not once per cycle. The MAAP cell builds and updates it manually alongside the Package Plan, typically as a DKS miz overlay, and it feeds forward into the ATO. There's no 639 CAOC web tool for this and there isn't meant to be one: the ACO needs to track a live, moving battle picture, and DKS already does that well.

owner: Combat Plans (MAAP cell) · cadence: every mission event, by design
6

Theater Comm Plan

Planned

The campaign's standing net/frequency matrix — TAC COORD, ASOC, STRIKE, SEAD, tanker nets, JTAC nets, and the rest. Built once before Cycle 1 by the MAAP cell and normally left alone for the campaign's full run; referenced here, alongside the ACO, as what the ATO compiles forward to squadrons. The actual frequencies are close to arbitrary; what matters is every group sharing the same matrix and the same standard channel set, so a large multi-group mission doesn't collide on comms.

owner: Combat Plans (MAAP cell) · cadence: per campaign, rare revision
7

ATO

Planned

The Air Tasking Order — every group's packages for the cycle, plus the current ACO and the standing Comm Plan, compiled into one tasking document and published out to all participating Discords/DKS at once. The last product before execution. Planned but not yet built; today each group works from its own Package Plan output, ACO overlay, and the Comm Plan directly.

owner: Combat Plans · cadence: every cycle
8

Mission Planning and Execution

Standing practice

Squadron-level work: aircrew sign-up, loadouts, briefing, and flying the package against the ATO. This happens whether or not the AOC has tooling for it — it's where the paper becomes a mission.

owner: Squadrons / Groups A–C · cadence: every mission
9

BDA / Debrief

Standing practice

Combined battle damage assessment and debrief, reported back up. It closes the fast loop into the next AOD's "what changed since last cycle" field every cycle, and — far less often — informs a revision of the Intent itself when the campaign's own shape has changed, not just its status.

owner: all groups, rolled up by CFACC · cadence: every cycle
